For a root template, each shown input must be `R + (Lst(xs),)` and its required output `R + (Lst(ys),)`, with exact typed equality of the rest R and equal list lengths. A single uncaptured body must map each singleton `(xs[j],)` to `(ys[j],)` across ALL shown occurrences. Contradictory outputs for the same typed element reject this template; they do not prove the whole task unsolvable. Empty lists impose no invocation constraints. Empty/identity bodies need an explicit check: ordinary beam has no root-fit shortcut.

The map runtime starts each invocation on `(item,)` and cannot read ambient R. Captures constructed into quotation code are different: changing captures can legitimately map equal items to different outputs. Excluding captures and unknown prefixes is a deliberate restricted proposal, not a theorem about every terminal map. Rejecting this template must fall back to ordinary search.

The inferred value pairs are not a sufficient finite-resource execution specification. `_run_map` spends1, passes decreasing `budget-cost` to each body, and invokes it at deeper quotation depth. Ordinary body beam resets DEFAULT_FUEL_LIMIT and depth0 before each primitive product call. A separately fitted body can fail after assembly. Source-derived illustration, NOT EXECUTED: on5000zero elements, a body of ten `1 add` pairs costs20per element, so a whole map needs100001fuel including its own1, above DEFAULT_FUEL_LIMIT100000. Independent successful body calls do not establish wrapper success. The eventual tests must check actual low primitives, not merely assert this arithmetic.

Nested quotation construction also changes runtime quotation depth and code/data placement. Fit the reconstructed full `[ ... ] map` program on original shown pairs before returning anything, under real original fuel/depth semantics. A first fitted body that fails assembly may be discarded and the remaining task budget sent to flat search; do not claim completeness or silently keep searching for a favourable body after seeing results.

Typed data must survive any body-task formatting. `format_stack` needs Config; printed brackets/symbols/Mark can be ambiguous. Require exact typed parse/format round-trip for every singleton pair; unsupported values mean ineligible/fallback. Reject top-level Mark body goals that the close guard cannot accept. Do not convert typed Int/Bool/Sym/Lst keys to bare Python scalars. Preserve repeated occurrence order/weight in the scorer; use duplicate consistency checks without silently deduplicating the neural input.
