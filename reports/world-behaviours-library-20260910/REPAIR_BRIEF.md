# Repair brief: witnesses that fail hypothesis-breaking inputs (#124, #125)

You are repairing `mark-28` programs (witnesses) for world-authored behaviours.
Run every command from the repository root you were started in. Do not commit,
push, or edit any tracked file. Your only output is one new file, named in
your instructions, in `reports/world-behaviours-library-20260910/`.

## Background

Each behaviour is an MBPP problem: a Python reference solution and tests. The
tests were regenerated by a sampler that, besides inputs like the original
asserts, deliberately **breaks** properties those asserts happened to share
(a negative number where all were positive, a duplicate where all were
distinct, an index outside the list). The rule for this corpus is that **the
reference solution is the behaviour**, including what it does on such inputs
(Python's negative indexing, truncating `int(x/2)`, an `if n <= 2: return n`
branch). A witness must reproduce the reference on every test, shown and
held-out, or it is not a witness.

Read `experiments/world_behaviours/REFERENCE.md` first (machine semantics,
idioms, the macro library). The library `experiments/world_behaviours/macros.txt`
is canonical; use its names. You may not add macros: write any helper inline
in the program.

## Commands

```bash
B=reports/world-behaviours-library-20260910/behaviours.jsonl
uv run python experiments/world_behaviours/verify.py $B --id mbpp-777 --show      # description, reference, every test
uv run python experiments/world_behaviours/verify.py $B --id mbpp-777 --program "min"   # pass count, first failures, expansion
```

The current program for each id, with its failing cases, is in
`reports/world-behaviours-library-20260910/programs_canonical.jsonl` (field
`program`). Start from it; most repairs are a guard for the newly drawn
inputs (`[ dup 0 lt? ] [ ... ] [ ... ] ifte`) around the existing program.

## Output

One JSON object per assigned id, one per line:

```json
{"id": "mbpp-777", "program": "<macro form that passes every test>", "status": "solved", "note": "what the reference does on the new inputs and how the program replays it"}
{"id": "mbpp-54", "program": "", "status": "unsolved", "note": "why: e.g. the reference's negative-index bucket writes are not worth replaying"}
```

`status: solved` only if `--program` reports passed == total. Budget about
15 minutes per id; an honest `unsolved` with the reason is a valid result and
is expected for a couple of these. When done, print the file's contents.
